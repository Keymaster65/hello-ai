= Backlog

Was als Nächstes zu tun ist – *ein Prompt je Überschrift*, von oben nach unten abzuarbeiten.
Die Überschrift *ist* der Prompt: Sie wird wörtlich als Aufgabe genommen, ein Rumpftext
darunter ist nur Notiz. Gezogen wird mit dem Befehl `next`, den der Skill
`docs/prompt/po.adoc` beschreibt
(link:{adr}/0028-backlog-als-anhang-mit-status-im-titel{adrext}[ADR 0028]). Welcher Eintrag der
nächste ist, hängt auch vom ausgecheckten Branch ab
(link:{adr}/0031-next-bevorzugt-branchgebundene-eintraege{adrext}[ADR 0031]).

.Der Anfang der Überschrift ist der Status
[cols="1,3", options="header"]
|===
| Anfang | Bedeutung

| `+:+`
| *ready* – darf mit `next` gezogen werden, auf jedem Branch.

| `+:+`<branch>
| *ready, an einen Branch gebunden* – z. B. `+:ai1+`, ohne Leerzeichen hinter dem `+:+`. Auf
  diesem Branch wird der Eintrag *zuerst* gezogen, auf jedem anderen gar nicht
  (link:{adr}/0031-next-bevorzugt-branchgebundene-eintraege{adrext}[ADR 0031]).

| `+*+`
| *aktiv* – wird gerade abgearbeitet. Es ist immer höchstens einer aktiv.

| `+KI+`
| *nicht ready* – Vorschlag einer KI. `next` übergeht sie.

| sonst
| *nicht ready* – Idee, Notiz, noch nicht spruchreif. `next` übergeht sie.
|===

Ein *erledigter* Eintrag wird *entfernt*, nicht abgehakt. Das Backlog beschreibt die Zukunft;
was getan wurde, steht im Session-Protokoll `docs/log/claudeLog.adoc` und in der Historie von
`git`.

== KI Beseitige die zwei Asciidoctor-Meldungen des Tasks asciidoctor

`+./gradlew asciidoctor+` meldet zweierlei, seit das Protokoll als Anhang „Änderungen"
eingebunden ist (ADR 0033): „section title out of sequence: expected level 2, got level 3" für
`docs/log/claudeLog.adoc` Zeile 3 – der Titel `+= Claude Log+` landet mit `+leveloffset=+2+`
eine Ebene zu tief unter dem Anhang – und „skipping reference to missing attribute: id". Der
Build bleibt grün, aber die Definition of Done verlangt „keine kritischen Warnungen";
`+asciidoctorPrompt+` und `+asciidoctorAdr+` laufen meldungsfrei.

== KI Härte den Abhängigkeitsweg des Builds gegen fremde Artefakte

Der Security-Skill verlangt bisher nur Versionskatalog und Herkunftsprüfung von Hand
(link:{adr}/0035-security-skill-und-security-txt{adrext}[ADR 0035], „Bewusst nicht getan").
Gemeint sind die Gradle-Mittel dafür: `+dependency-verification.xml+` mit
`+org.gradle.dependency.verification=strict+`, ein Schreibschutz für die Lockdatei und eine
Wartezeit, bevor eine frisch veröffentlichte Version verwendet wird. Jedes davon ist eine
Entscheidung mit Folgen für jeden Build – deshalb zuerst ein ADR.

== KI Richte einen vertraulichen Meldeweg für Schwachstellen ein und trage ihn in die security.txt

Die ausgelieferte `security.txt` nennt heute die *öffentlichen* Issues des Repositories
(link:{adr}/0037-security-txt-am-ursprung-per-engine-valve{adrext}[ADR 0037]) – eine Meldung ist
damit ab der ersten Zeile bekannt. In Frage kommen GitHub Security Advisories oder eine
gepflegte Adresse; beides ist eine Festlegung außerhalb des Codes und braucht danach nur noch
den Konfigurationswert `SECURITY_TXT_CONTACT`.

== KI Signiere die security.txt nach RFC 9116

RFC 9116 erlaubt eine Clearsign-Signatur samt `Signature`-Feld. Ohne sie ist der Inhalt der
Datei nicht als echt nachweisbar. Der Schritt verlangt einen gepflegten Schlüssel und damit ein
eigenes ADR – so schon in
link:{adr}/0035-security-skill-und-security-txt{adrext}[ADR 0035] festgehalten.

== KI Miss die Abdeckung modulübergreifend mit dem Plugin jacoco-report-aggregation

Aus link:{adr}/0047-testabdeckung-als-eingecheckte-tabelle{adrext}[ADR 0047], „Bewusst nicht
getan": Heute misst jedes Modul für sich, und was die Tests eines Moduls in einem *anderen*
ausführen, zählt nirgends – der Integrationstest in `:bootstrap` fährt den ganzen Stapel durch,
in der Zeile `:adapter` sieht man davon nichts. Das Plugin wertet die Ausführungsdaten aller
Module gegen alle Klassen aus; die Zeile `+*Summe*+` wäre dann eine Messung statt einer Addition.

== KI Setze Sicherheits-Header für die Auslieferung der SPA

Aus `docs/system/betrieb.adoc`, „Offene Punkte": Weder Content Security Policy noch
`X-Content-Type-Options`, `Referrer-Policy` oder `X-Frame-Options` werden gesetzt. Welche Policy
gilt und wo sie entsteht – in der Anwendung oder im vorgelagerten Proxy –, ist eine Entscheidung
mit Folgen für jede Antwort und braucht deshalb zuerst ein ADR; der Frontend-Skill verweist
darauf (`docs/prompt/security-frontend.adoc`, „Abgrenzung").

== KI Entferne die zwei Fremdzeilen am Ende von ADR 0048

`docs/adr/0048-security-skill-je-seite.adoc` endet mit `+</content>+` und `+</invoke>+` – Reste
eines Werkzeugaufrufs, die beim Rendern als Text mitten im Dokument stehen. Es ist kein Satz der
Entscheidung, also kein Umschreiben eines ADR (ADR-Skill, Grundsatz 3), sondern das Beseitigen
eines Artefakts.

== KI Nenne im README das Fehlerformat RFC 9457 statt ErrorResponse

`README.md` schreibt unter „REST-API": Nicht gefundene Rezepte und Validierungsfehler kommen
„jeweils als `ErrorResponse`". Das Format ist seit
link:{adr}/0046-rfc-9457-problem-details-als-fehlerformat{adrext}[ADR 0046] `ProblemDetail` mit
`+application/problem+json+`; die Systemdokumentation sagt es richtig, der Einstieg nicht.

== KI Schreibe ein ADR über die Kapitelstruktur der ADRs

Die 19 älteren ADRs sind auf Kapitel umgestellt worden, ohne dass eine Entscheidung dazu
festgehalten wäre. ADR 0026 hatte „Keine Umbenennung der Überschriften" ausdrücklich unter
„Bewusst nicht getan" geführt – der Schritt darüber hinaus gehört begründet, samt der Grenze:
Struktur ja, Text nein.

== KI Zeig im Beispielrumpf von POST /api/mcp/tools/\{name} echte Werkzeugargumente

Die Swagger UI rendert den Rumpf der Operation als Freiform-Objekt und zeigt deshalb
`+additionalProp1..3: "string"+`. Wer die Operation zum ersten Mal öffnet, sieht damit *nicht*,
dass dort etwa `+{"id": 1}+` hingehört – die Argumente stehen je Werkzeug in `+inputSchema+` unter
`+GET /api/mcp/tools+`. Eine `+@RequestBody+`-Annotation mit `+example+` würde das ohne ein
typisiertes DTO je Werkzeug beheben; die Doppelung der Werkzeugliste, die
link:{adr}/0050-rest-facade-des-mcp-service-in-openapi{adrext}[ADR 0050] verworfen hat, entstünde
dabei nicht.
