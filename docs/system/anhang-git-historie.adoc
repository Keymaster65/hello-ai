[[git-historie]]
= Git-Historie

Die zweite Sicht auf dieselbe Arbeit, die <<session-protokoll>> aus der Richtung des Prompts
zeigt: *was* das Repository verändert hat, ein Eintrag je Commit
(Skill `docs/prompt/systemdokumentation.adoc`).

Die Tabelle unten wird bei jedem Build aus der git-Historie *erzeugt* – vom Gradle-Task
`gitChangelog`. Sie liegt deshalb nicht im Repository, sondern entsteht unter `build/` und wird
von dort eingebunden: Ein Commit kann sich selbst nicht enthalten, eine eingecheckte Fassung
wäre ab ihrem Entstehen um genau einen Commit alt.

Neuester Commit oben – dieselbe Richtung wie im Protokoll und in der
Kennzahlen-Tabelle. Der Kurz-Hash benennt den Commit, der Betreff ist die *erste Zeile* seiner
Message; der Rumpf samt `Co-Authored-By`-Zeile bleibt draußen.

Die Spalte *„Prompt"* nennt die Einträge des Protokolls, aus denen der Commit hervorgegangen
ist (Skill `docs/prompt/butterfly.adoc`). Sie ist
*abgeleitet*: Gelesen wird allein die Zeile `+_Commit:_+` des jeweiligen Eintrags, nicht dessen
Fließtext. Ein `–` heißt deshalb nicht „kein Prompt", sondern *„kein Eintrag schreibt sich
diesen Commit zu"* – bei den Commits, die vor dieser Entscheidung entstanden sind, ist das die
Regel. In die Gegenrichtung zeigt der Anker `+commit-<kurzhash>+` jeder Zeile, auf den das
Protokoll und die Kennzahlen-Tabelle in <<kennzahlen>> verweisen
(Skill `docs/prompt/manager.adoc`).

Zwei Auslassungen gehören dazugesagt, damit die Tabelle nicht als lückenlose Liste gelesen wird:

* *Von git erzeugte Zusammenführungen* (`Merge branch …`) fehlen. Sie tragen keine eigene
  Änderung, sondern nur die Naht zwischen zwei Branches
  (Skill `docs/prompt/develop.adoc`).
* *Aufgehobene Commits* fehlen samt ihrem `Revert`. Das Werkzeug erkennt die Zeile
  `This reverts commit …` und lässt beide Seiten weg. Die Tabelle zeigt damit, was *geblieben*
  ist – nicht jeden Schritt, der einmal getan wurde. Vollständig ist allein `git log`.
